# NNUE 训练验证策略方案

> 生成时间：2026-10-02 12:45  
> 任务 ID：6  
> 问题背景：200-500 局对弈 Elo 置信区间 ±30，无法分辨 <15 的改进；41 维 SPSA + 200 局/评估噪声过大未收敛

---

## 1. 问题诊断

### 1.1 当前验证噪声分析

| 验证规模 | CI 半宽 | 可分辨 Elo | 实测耗时 | 状态 |
|----------|---------|-----------|---------|------|
| 200 局 | ±48 | >96 | ~4 min | 噪声过大，无法判定 |
| 500 局 | ±30.5 | >61 | ~11 min | 无法分辨 <15 的改进 |
| 5000 局 | ±9.63 | >19 | ~18 min | 无法分辨 <15 的改进 |
| 10000 局（预期） | ±6.81 | >14 | ~37 min | 临界可分辨 Elo=15 |
| 20000 局（预期） | ±4.82 | >10 | ~74 min | 可分辨 Elo=10 |

**核心矛盾**：NNUE 单层训练的典型改进幅度 3-15 Elo，而 5000 局的 CI=±9.63 仍无法可靠分辨。

### 1.2 噪声来源

1. **对弈随机性**：开局选择、先后手、搜索不确定性引入 ±30 Elo 级噪声
2. **和棋率偏高**：10000 节点/局下和棋率 ~43%，降低区分度
3. **小样本偏差**：500 局时点估计漂移可达 ±30 Elo

## 2. 方案一：大样本 SPRT 管线

### 2.1 样本量计算

#### 理论依据

Elo 置信区间半宽与对弈局数 N 的关系：

```
CI_half ≈ Z_{α/2} × σ_Elo / √N
```

其中 σ_Elo（单局 Elo 标准差）可从已有数据反算：

```
σ_Elo = CI_half_5000 × √5000 = 9.63 × 70.71 ≈ 681 Elo·√局
```

#### 目标分辨力下的最小局数

| 目标分辨 Elo | 所需 CI 半宽 | 最小局数 N | 备注 |
|-------------|-------------|-----------|------|
| 30 | 15 | 2,050 | 当前 5000 局已超过 |
| 15 | 7.5 | 8,200 | 临界可用 |
| 10 | 5.0 | 18,500 | 推荐（可靠分辨） |
| 5 | 2.5 | 74,000 | 高置信验证 |

> 取 α=0.05（Z=1.96），实际需考虑 SPRT 提前停止可减少局数 20-40%。

### 2.2 SPRT 停止准则

#### 假设设定

```
H0: Elo ≤ elo0  (无改进或退化)
H1: Elo ≥ elo1  (有显著改进)
```

#### 参数配置

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| elo0 | 0 | 无改进 |
| elo1 | 15 | 目标改进幅度 |
| α（假阳性率） | 0.05 | 5% 概率误判有改进 |
| β（假阴性率） | 0.05 | 5% 概率漏判改进 |
| LLR 上界 | +2.944 | ln((1-β)/α)，PASS H1 |
| LLR 下界 | -2.944 | ln(β/(1-α))，FAIL H0 |

#### LLR 计算（基于 Bayes Elo 模型）

```python
import math

def sprt_llr(wins, losses, draws, elo0, elo1):
    """基于 Bayes Elo 的 SPRT 对数似然比"""
    N = wins + losses + draws
    # 胜/负/和概率的 MLE
    p_w, p_l, p_d = wins/N, losses/N, draws/N
    # 将 Elo 转为 Bayes 模型的胜/和/负概率
    # （简化：用 logistic 胜率近似）
    def elo_to_probs(elo, draw_ratio=p_d):
        p_win = (1 - draw_ratio) / (1 + 10**(-elo/400))
        p_loss = (1 - draw_ratio) - p_win
        return p_win, p_loss, draw_ratio
    # LLR = LL(H1) - LL(H0)
    ll = lambda pw, pl, pd: wins*math.log(pw) + losses*math.log(pl) + draws*math.log(pd)
    pw0, pl0, pd0 = elo_to_probs(elo0)
    pw1, pl1, pd1 = elo_to_probs(elo1)
    return ll(pw1, pl1, pd1) - ll(pw0, pl0, pd0)
```

#### 停止规则

```
if LLR >= +2.944:  → PASS（接受 H1，有改进）
if LLR <= -2.944:  → FAIL（接受 H0，无改进）
else:              → CONTINUE（继续对弈）
```

## 3. 方案二：残局知识库确定性验证

### 3.1 设计理念

不依赖随机对弈，而是用**已知正确答案的残局集合**做确定性验证：
对每个残局，检查引擎最优走法是否匹配已知正解。无随机噪声，结果完全可复现。

### 3.2 残局知识库构建

#### 数据来源

| 来源 | 数量 | 可靠度 | 获取难度 |
|------|------|--------|---------|
| 中国象棋残局经典（棋谱书） | 100-500 | 高（人工验证） | 中（需数字化） |
| 引擎自对弈 + 人工标注 | 50-200 | 中 | 高 |
| 象棋软件公开残局库 | 200-1000 | 中-高 | 低 |
| 合成残局（已知唯一最优解） | 100-500 | 高 | 低（程序生成） |

#### 残局库格式

```json
{
  "id": "endgame_001",
  "fen": "3ak4/9/9/9/9/9/9/9/4A4/3AK4 w",
  "best_move": "d0e1",
  "category": "车胜士象全",
  "depth_verified": 30,
  "source": "经典残局大全"
}
```

#### 覆盖维度

| 类别 | 示例 | 目标数量 |
|------|------|---------|
| 兵类残局 | 单兵胜单士、兵士对单士 | 20+ |
| 车马类 | 车马对车双象、车马冷着 | 30+ |
| 炮类 | 炮士胜单士、空头炮 | 20+ |
| 复杂残局 | 车马炮对车马炮 | 30+ |
| 实用残局 | 棋谱中常见残局 | 50+ |
| **合计** | | **150-200** |

### 3.3 验证流程

```python
def verify_endgame_knowledge(engine, knowledge_base):
    """残局知识库确定性验证"""
    results = []
    for entry in knowledge_base:
        # 1. 加载残局
        engine.uci(f"position fen {entry['fen']}")
        # 2. 搜索到指定深度
        engine.uci(f"go depth {entry['depth_verified']}")
        best_move = engine.wait_for_bestmove()
        # 3. 比对正解
        match = (best_move == entry['best_move'])
        results.append({
            "id": entry["id"],
            "fen": entry["fen"],
            "expected": entry["best_move"],
            "actual": best_move,
            "match": match,
        })
    # 4. 汇总
    n_match = sum(r["match"] for r in results)
    return {
        "total": len(results),
        "matched": n_match,
        "accuracy": n_match / len(results),
        "details": results,
    }
```

### 3.4 优缺点分析

| 方面 | 优点 | 缺点 |
|------|------|------|
| 噪声 | **无随机噪声**，完全确定性 | — |
| 速度 | **秒级**完成 200 个残局验证 | — |
| 可复现 | **完全可复现**，同一网络同一结果 | — |
| 覆盖面 | — | **有限**，仅覆盖残局，不覆盖中局 |
| 改进灵敏度 | 能检测走法级错误 | 无法量化 Elo 改进幅度 |
| 假阴性 | — | 残局正解可能不唯一（多解走法） |
| 维护 | — | 需人工维护正解，成本较高 |

### 3.5 适用场景

- ✅ **训练过程门控**：每次训练迭代后快速 sanity check（秒级）
- ✅ **回归测试**：确保新训练不破坏已知残局求解能力
- ✅ **走法级 bug 检测**：发现引擎走法错误
- ❌ **Elo 量化**：无法替代对弈验证给出 Elo 数值
- ❌ **中局改进验证**：残局不覆盖中局局面

## 4. 方案三：混合验证策略（推荐）

### 4.1 分层验证流水线

```
┌─────────────────────────────────────────────────────┐
│              训练后网络验证流水线                    │
├─────────────────────────────────────────────────────┤
│                                                     │
│  层 1：Bench 节点数检查（秒级）                     │
│  ├─ 跑 bench，对比基准节点数                        │
│  ├─ 偏离 >5% → 警报尺度偏移                        │
│  └─ 通过 → 进入层 2                                │
│                                                     │
│  层 2：残局知识库验证（分钟级）                     │
│  ├─ 200 个残局，检查最优走法匹配率                  │
│  ├─ 准确率 < 95% → 警报走法退化                     │
│  └─ 通过 → 进入层 3                                │
│                                                     │
│  层 3：快速 Elo 探测（~5 分钟，1000 局）            │
│  ├─ 1000 局并发对弈，CI ≈ ±21                      │
│  ├─ Elo < -30 → 拒绝（明显退化）                   │
│  ├─ Elo > +30 → 直接进入层 5（明显改进）           │
│  └─ 其他 → 进入层 4                                │
│                                                     │
│  层 4：大样本 SPRT（~30 分钟，10000+ 局）           │
│  ├─ SPRT H0: Elo≤0 vs H1: Elo≥15, α=β=0.05         │
│  ├─ PASS → 接受改进，进入层 5                       │
│  ├─ FAIL → 拒绝，训练无改进                         │
│  └─ CONTINUE → 补到 20000 局                        │
│                                                     │
│  层 5：高精度确认（~70 分钟，20000 局）             │
│  ├─ 20000 局 / 20k 节点，CI ≈ ±4.8                  │
│  └─ 输出最终 Elo ± CI，归档结果                     │
│                                                     │
└─────────────────────────────────────────────────────┘
```

### 4.2 各层耗时与决策

| 层 | 耗时 | 通过条件 | 未通过处理 |
|----|------|---------|-----------|
| 1. Bench | ~5 s | 偏离 <5% | 警报尺度偏移，回训练 |
| 2. 残局库 | ~1 min | 准确率 ≥95% | 分析失败残局，回训练 |
| 3. 快速 Elo | ~5 min | -30 < Elo < +30 之外有明确判定 | 中间值进层 4 |
| 4. SPRT | ~30 min | LLR 触及 ±2.944 | CONTINUE 则进层 5 |
| 5. 高精度 | ~70 min | 最终 Elo ± CI | 归档 |

**总耗时**：最佳路径（层 1-3 明确判定）~6 min；最坏路径（全 5 层）~106 min。

### 4.3 与现有工具的集成

| 层 | 现有工具 | 需新增 |
|----|---------|--------|
| 1 | `src/pikafish` bench 命令 | 自动化脚本对比基准 |
| 2 | — | `tools/verify_endgames.py` + 残局库 JSON |
| 3 | `tools/elo_match_parallel.py`（减少局数） | 无 |
| 4 | `tools/elo_match_parallel.py`（增加局数） | SPRT 提前停止已实现 |
| 5 | `tools/elo_match_parallel.py` | 无 |

## 5. 推荐方案

### 5.1 短期（立即可行）

**采用方案三（混合验证）的层 1-4**：

1. **构建残局知识库**（~200 个残局，1-2 小时人工整理）
2. **实现 `tools/verify_endgames.py`**（~半天开发）
3. **训练后先跑层 1-2**（秒级-分钟级门控）
4. **通过后跑层 4 大样本 SPRT**（10000 局，elo0=0, elo1=15，~30 min）

**理由**：残局库可一次性投入后反复使用，将 80% 的"明显退化/无改进"训练结果在分钟级淘汰，
只对 20% 的"可能有改进"结果投入 30 分钟级 SPRT，大幅节省验证资源。

### 5.2 中期（1-2 周）

- 扩展残局知识库至 500+ 个
- 将 `elo_match_parallel.py` 扩展为支持远程 worker 的 fishtest 轻件
- 引入 SPRT 自动调参（根据历史改进幅度动态设 elo1）

### 5.3 长期（1 月+）

- 构建中国象棋开局集（1000+ FEN）用于 fishtest
- self-play 数据迭代闭环
- 多种子训练 + Elo 集成验证

### 5.4 不推荐的做法

| 做法 | 问题 |
|------|------|
| 仅用 500 局对弈判定 | CI=±30，无法分辨 <15 的改进，等于盲猜 |
| 每次训练都跑 20000 局 | 耗时 70+ min，迭代效率极低 |
| 仅用残局库验证 | 无法量化 Elo，无法覆盖中局 |
| 41 维 SPSA + 200 局/评估 | 噪声/信号比过大，无法收敛（当前失败原因） |

## 7. 总结

| 问题 | 方案 | 预期效果 |
|------|------|---------|
| ±30 Elo 噪声 | 大样本 SPRT ≥10000 局 | CI 收窄至 ±7，可分辨 Elo=15 |
| 验证耗时长 | 分层流水线（残局库先行） | 80% 训练结果分钟级淘汰 |
| 覆盖面不足 | 残局库 + 对弈互补 | 确定性 + 统计性双重保障 |
| SPSA 不收敛 | 改用大样本 SPRT 评估 | 每次评估噪声可控 |

**核心建议**：不要在噪声中寻找信号。先用确定性验证（残局库）淘汰明显错误，
再对候选结果投入足够样本（≥10000 局）做统计判定。
